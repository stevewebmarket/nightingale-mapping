# Milestones

Single source of truth for milestone numbers. Generated by `run_milestones.py`,
deterministic across runs. Replace these numbers only by re-running the script.

## How to reproduce

```bash
git clone https://github.com/stevewebmarket/nightingale-mapping.git
cd nightingale-mapping
pip install -r requirements.txt
python scripts/fetch_samples.py     # downloads orchestra.wav + rock.wav
python run_milestones.py
```

The script is deterministic. Three consecutive runs in the development
environment produced byte-identical output.

## Method

Two real-world recordings are used: a 15 s orchestral excerpt sustained near
83 Hz and a 15 s rock excerpt with bass + lead. Both clips are taken from
the `samples-v1` GitHub Release on this repo.

For each clip, `librosa.onset.onset_detect` finds the first 8 onsets in the
original waveform. Each test then applies one transform and compares the
median YIN pitch on the matched per-onset segment.

### M1.2 — Pitch shift (resampling)

The shift is performed by **pure resampling**, not by phase vocoder. The
audio is reinterpreted as if it had been sampled at `1.5 × 44100` Hz and then
downsampled back to `44100` Hz. This raises pitch by exactly 1.5× *and*
compresses duration by 1/1.5×. An onset at original time `t` therefore lands
at `t / 1.5` in the shifted signal.

Per-note score = `pitch_shifted / pitch_original`, expected ≈ 1.5.
A note counts as correct if its measured ratio is within 1% of 1.5
after octave-folding.

### M1.3 — Time stretch (phase vocoder)

The stretch is performed by `librosa.effects.time_stretch(rate=1/1.5)`,
making the audio 1.5× longer while preserving pitch. An onset at original
time `t` lands at `t × 1.5` in the stretched signal.

Per-note score = `pitch_stretched / pitch_original`, expected ≈ 1.0.
Counts as correct within 1%, octave-folded.

### M1.4 — Composition (shift then stretch)

Apply M1.2 then M1.3 back to back. Net duration change is `(1/1.5) × 1.5 = 1`,
so onsets land at original time `t`. Pitch invariant from M1.2 must still
hold: per-note ratio expected ≈ 1.5, within 1% tolerance, octave-folded.

This is the no-drift check: if the two transforms compose cleanly under the
extraction pipeline, the composed score should not collapse relative to the
two individual scores.

## Octave folding

YIN can lock onto any harmonic of the true fundamental (the octave below,
the octave above, etc.). Two notes whose true ratio is 1.5 may yield a YIN
pitch ratio of 0.75 (= 1.5 / 2) or 3.0 (= 1.5 × 2) instead. Octave-folding
multiplies or divides by 2 until the ratio is in `[target / √2, target × √2]`,
which is the correct equivalence class for "same musical interval, different
detected harmonic".

Both the raw and octave-folded scores are printed by `run_milestones.py` so
the harmonic effect is auditable.

## What this does not claim

- It does not claim that the pipeline recovers melodic content from arbitrary
  music, only that **pitch ratios at detected onsets** are preserved within 1%
  under these specific transforms on these specific clips.
- It does not claim novelty of the underlying signal-processing steps. YIN,
  phase-vocoder time stretch, and onset detection are standard tools. The
  contribution being measured is the **end-to-end invariance of the
  ratio-of-pitches representation** across two musically meaningful
  transforms and their composition.
